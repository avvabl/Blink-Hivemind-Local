# Hivemind Schema Conventions

## Feature file frontmatter (`feature.md`)

```yaml
---
product: <product-slug>                  # required; use taxonomy.md slugs
feature: <feature-slug>                  # required; human-assigned
status: live | in-development | deprecated | removed
clients_with_overrides: []               # list of client slugs with override pages
related: []                              # wikilinks to related features
tags: []                                 # free-form tags
last_updated: YYYY-MM-DD
---
```

## History file entry (`history.md`)

Each entry follows this format, prepended at the top (newest first):

```markdown
## YYYY-MM-DD — <author>
- **Section touched:** <section name>
- **Type:** update | client-specific | new | cancel
- **Summary:** <one-line human-readable summary>
- **AI reasoning:** <why the LLM filed it here>
- **Source:** [[transcripts/YYYY/MM/<slug>]]
```

## Client override frontmatter (`clients/<slug>.md`)

```yaml
---
product: <product-slug>
feature: <feature-slug>
client: <client-slug>
override_type: feature-flag | bespoke
status: active | inactive
last_updated: YYYY-MM-DD
---
```

## Decision file frontmatter (`decisions/<slug>.md`)

```yaml
---
type: decision
scope: ecosystem | <product-slug>
status: active | superseded | reversed
date: YYYY-MM-DD
---
```

## Auto-generated files

Files marked `auto_generated: true` in frontmatter are **never hand-edited**. They are regenerated by the app on every ingestion commit:

- `_index.md` in every product and feature folder
- `_meta/vault-index.md`
- `clients/<slug>/overrides.md`
